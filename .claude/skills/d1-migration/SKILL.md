# Create and apply a D1 migration

The database is Cloudflare D1 (binding `DB`, db `angular-lab-db`, configured in `wrangler.jsonc`). Migrations are plain numbered `.sql` files applied in order.

## Convention

- Files live in `migrations/`, named `NNNN_short_description.sql` (zero-padded, incrementing). Current highest wins — check `ls migrations/` and use the next number.
- Use idempotent DDL (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`) so re-runs are safe.
- Foreign keys reference existing tables (e.g. `REFERENCES users(id) ON DELETE CASCADE`). Look at `migrations/0003_progress.sql` for the house style.

## Steps

1. Create `migrations/NNNN_your_change.sql` with the next number and idempotent DDL.
2. Apply locally: `pnpm db:migrate` (wraps `wrangler d1 migrations apply angular-lab-db --local`). This writes to local `.wrangler` state only.
3. Test with functions running: `pnpm dev:pages` (port 8788) — plain `pnpm dev` (5173) has **no** Pages Functions or D1, so anything touching the DB will fail there.
4. If the change affects authentication or sessions, **also update `specs/auth.md`** (project convention).
5. Production migrations run against the remote D1 during deploy — do not point `--local` commands at prod.

## Seeding

Seed data goes in its own migration (see `migrations/0002_seed_demo_user.sql`). Password hashes are generated by `scripts/generate-demo-hash.mjs` (PBKDF2-SHA256), not written by hand.
